# Independent review dispositions

A first independent reviewer returned a failing verdict against an earlier snapshot. Findings were examined, not automatically accepted or dismissed.

- **Trust flags and pattern filtering:** accepted as a limitation, not a guarantee. The queue is an explicit trusted public projection written by the companion/session operator. The service never scans raw notes. `ops/README.md` states that pattern matching cannot certify privacy. Deploy prerequisites restrict write access to the operator, and the code now also rejects world-writable queue/output directories. A human/user-approved publication boundary is not replaced by a regex score.
- **Private DNS resolution:** no SSRF path exists: queued entry URLs are rendered as links and are never fetched by the publisher. Literal IP/local names and credentials are rejected; DNS resolution must be added if link preview/fetching is introduced. This remains an explicitly documented non-fetching boundary, not claimed DNS safety.
- **External link relationship:** work-page external links now carry `rel="noopener noreferrer"`, matching the journal.
- **Duplicate/update semantics:** two files cannot silently claim the same ID: a flat queue requires each filename stem to equal its entry ID. Same ID is intentionally an update, and a test proves replacement without duplication. The exact filename identity check was already present in the reviewed snapshot. Existing curated case studies are not silently overwritten by generated content; this legacy boundary is documented.
- **Push-failure recovery:** the claim that an ahead commit necessarily makes `git status --porcelain` dirty is incorrect. A new real local Git transport test creates an actual rejecting pre-receive hook, observes the failed push, confirms the worktree is clean, removes the hook and successfully retries the same commit. No network response or Git outcome is fabricated.
- **Unexpected ahead commits:** a real additional risk was closed: retries now inspect every pending commit's changed files and reject merges or any non-projection path. A second actual Git test proves that a clean tree with unrelated ahead work cannot be pushed by the content worker.
- **Atomic replacement:** `os.replace` replaces the directory entry and does not follow a destination symlink. The code refuses symlink targets, symlink output parents and world-writable output directories. Repository/state parents must remain trusted and operator-owned; this is a deployment prerequisite rather than a claim to defend a hostile filesystem owner.
- **Remote state:** no server installation, timer first run or production restore drill has been claimed. The current public project status is in-progress.

Current local gates: 186 TypeScript/Vitest tests, 13 Python tests including actual Git transport, and 98 browser tests (before the link-rel-only change). Final independent rereview and production verification remain separate gates.
